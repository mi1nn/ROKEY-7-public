- 로봇은 한 대에 한 사람만 움직인다([작업 규칙](../../AGENTS.md) 6절). TB1 은 이태규, TB2 는 전제환이다. 오케스트레이터는 임무만 보내고 Nav2 목표·취소는 `rescue_robot` 이 낸다.
- 서로 대신해 줄 사람: 전제환(TB2) → 백승민, 이태규(TB1) → 전제환(같은 로봇 코드), 박세준 ↔ 정해윤(같은 탐지 계열), 임재범 ↔ 박주은(같은 DB·화면), 백승민(문서) → 정해윤.
- 알고리즘 선택(정해윤): 무엇을 고르게 할지(SLAM 방식, 탐색 방식 등)는 아직 모른다 [미확인]. 10-10 저녁에 이태규와 정한다. 탐색 방식 자체가 열린 질문(Q-24)이고, [알고리즘 결정](../design/algorithm-decisions.md)은 지도 백엔드를 바꿀 수 있게 경계를 두자고 제안한다. 고치는 파일은 기반 레인(`src/rescue_mapping/`·`src/rescue_robot/`)이라 이태규와 PR 본문에 먼저 나눠 적는다([작업 규칙](../../AGENTS.md) 2절). 이태규의 TB1 실기(10-12)가 통과한 뒤에 붙이고, 동결(10-14 저녁)까지 안 되면 발표 뒤 목록으로 넘긴다.
- 평가 항목과의 연결 [강의: [원본 평가표](https://github.com/jaebeom/ROKEY_P4/blob/1a2d0a9811f59a501c7597edf54c72fec8a80e26/docs/reference/2026-10-01-course-schedule-evaluation.md#L75-L91)]: 흐름도 30점과 SDD 는 백승민이 쓰고 각 담당이 자기 부분을 검토한다. Detection·AMR·System Monitor 모듈 시험(각 10점)은 박세준·이태규·박주은이 정리한다.
- 담당이 없는 것: 온도·히트맵, 중앙 경로 예약·교착 복구(Part I 후순위), 기준 지도 대비 장애물 변화 표시(Part I 에 없음, Q-24).
- 임재범은 오케스트레이터와 웹을 같이 맡아 10-10 ~ 10-13 대부분의 칸에서 일이 둘 겹친다. 공통 규격은 Claude 작전·총괄 세션이 초안을 쓰고 임재범은 결정만 한다.

## 3. 일정표 쓰는 법

[schedule-timeline.csv](schedule-timeline.csv) 는 기존 구글 시트 "Time Line." 탭과 같은 열 순서다: 카테고리 / 항목 / 구분 / 세부항목 / 비고 / 담당자 / 진행 상황, 그 뒤에 날짜별 오전·오후·저녁 칸.

- 구글 시트에서 `파일 → 가져오기 → 업로드` 로 CSV 를 열고, `■` 칸에 색을 칠한다.
- `비고` 의 `CP` 는 핵심 경로 작업이다. "CRITICAL PATH ITEM" 탭으로 옮길 때 이 줄만 고르면 된다.
- `진행 상황` 은 0(시작 전) ~ 1(완료)이다. 매일 저녁 담당자가 고치고, PM 이 막힌 것을 정리한다.
- `담당자` 가 `전원` 인 줄은 7명 모두다. 사람별로 보려면 이 열로 필터한다.
- 일정을 바꿀 때는 이 CSV 를 고치는 PR 을 연다. 시트와 저장소가 어긋나면 저장소가 기준이다.
