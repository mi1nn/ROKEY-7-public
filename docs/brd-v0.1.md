# 재난 대응 AMR 구조 지원 시스템 BRD (v0.1 초안)

Oct 8, 2026 · @min

## 문서 개요

이 문서는 팀 시나리오(지진 감지 → 정찰 → 구조 지원 → 출구 확인 → 완료 판정)를 사업 요구사항으로 정리한 v0.1 초안입니다. 강사 양식의 순서(목표, 범위, 기능·비기능 요구, 종속·제약, 위험, 수락 기준)를 유지하고, 그 사이에 상황·니즈 분석, Use Case, 상업적·기술적 요구사항을 추가했습니다.

| 표기 | 뜻 |
| --- | --- |
| \[확정\] | 팀 시나리오에 적힌 내용 |
| \[제안\] | 이 초안에서 구체화한 내용, 팀 합의 필요 |
| \[가정\] | 확인 전에 임시로 둔 전제 |
| \[미결정\] | 팀 결정이 필요한 항목, 13장에 모음 |

모든 목표 수치는 제안값이며 시험 전에 확정합니다. 확정 전에는 합격 판정에 쓰지 않습니다. 외부 사실은 출처 링크를 달고, 확인하지 못한 값은 비워 둡니다.

## 1. 상황 분석

지진 직후 건물 내부는 사람이 들어가기 전에는 통로 상태와 요구조자 위치를 알 수 없고, 이 정보 공백이 구조 지연과 구조 인력의 위험 노출으로 이어집니다. \[제안\]

### 1.1 배경

- 국내 지진은 대부분 소규모입니다. 기상청 지진연보 보도자료에 따르면 규모 2.0 이상은 2025년 79회, 1999\~2024년 연평균 72.8회이고 2025년 최대 규모는 태안 해역 ML 3.7입니다. ([기상청 2025 지진연보 보도자료](https://www.kma.go.kr/kma/flexer/html/press/2026/02/25/ATC202602250826292_822db418-a6fe-4b07-987b-cfaca5808a9e.hwp.files/Sections1.html), 2026-02-25 발간)
- 따라서 이 시스템의 근거는 지진 빈도가 아니라 발생 시 인명 피해가 큰 저빈도 사건에 대한 대비와 평시 활용에 둔다. \[제안\]
- 지진 생존자의 90% 이상이 사흘(72시간) 이내 구조된다는 전문가 발언이 있습니다. AFP 인용 보도이며 원자료는 확인하지 못했습니다. 이 문서는 "초기 대응 시간이 중요하다"는 수준으로만 사용합니다. ([뉴시스, 2023-02-09](https://mobile.newsis.com/view/NISX20230209_0002187565))

### 1.2 현행 대응 방식과 한계

아래는 일반적인 추론이며 현장 조사나 문헌으로 확인하지 않았습니다. \[가정\]

| 방식 | 한계 |
| --- | --- |
| 구조 인력이 직접 진입해 수색 | 붕괴·여진 위험에 노출되고, 변화된 통로 지도 없이 탐색해야 함 |
| 고정 CCTV 확인 | 시야 밖 공간은 볼 수 없고, 지진으로 카메라가 흔들리거나 가려질 수 있음 |
| 사전 평면도 기반 계획 | 지진 후 바뀔 통로 상태(장애물)를 반영하지 못함 |

### 1.3 이해관계자

| 이해관계자 | 시나리오에서의 접점 | 표기 |
| --- | --- | --- |
| 관리자 | 관리자 화면에서 지도, 사람 위치, 구조 인원 수를 확인 (6번) | \[확정\] |
| 구조 대상자 | 로봇이 탐지하는 대상. 시연에서는 인형으로 대체 | \[확정\] |
| 현장 구조 인력 | 구급상자를 받고 구조를 수행. 5번 "사람과 같이 출발"의 해석에 따라 달라짐 | \[미결정\] |
| 건물 소유·운영자 | 시스템 도입·운영 주체 | \[제안\] |

### 1.4 문제 정의

지진으로 건물 내부 상태가 바뀔 직후, 구조 인력이 진입하기 전에 요구조자의 위치와 접근 가능 여부를 자동으로 파악할 수단이 없다. \[제안\]

해결 방향은 고정 카메라로 지진 징후를 감지하고, 정찰 로봇이 지도를 갱신하며 사람 위치를 찾고, 구조 지원 로봇이 구급상자를 싣고 출동하는 것이다. \[확정\]

## 3. 비즈니스 목표 (Business Objectives)

지진 직후 구조 인력이 진입하기 전에 요구조자의 위치와 통로 상태를 파악하는 AMR 기반 시스템을 개발해, 건물 운영자와 방재 담당자에게 판매 또는 임대하는 것이 목표이다. 이를 통해 구조 인력의 위험 노출과 탐색 시간을 줄이는 것이 제안 가치이다. \[제안: 판매·임대 방식은 6장\]

| ID | 목표 | 연결 니즈 |
| --- | --- | --- |
| BO-01 | 지진 징후 감지부터 요구조자 위치 저장·통지까지 자동으로 연결한다 | N-01, N-02, N-03 |
| BO-02 | 두 로봇이 정찰과 구조 지원을 나눠 병행한다 | N-03, N-04 |
| BO-03 | 구조 결과를 관리자가 실시간으로 확인한다 | N-05, N-06 |
| BO-04 | (옵션) 평시 모니터링으로 도입 가치를 높인다 | N-07 |

### 성공 지표

모든 값은 시연 환경 기준 제안값이다. 반복 횟수 N과 합격 기준은 시험 전에 확정한다. 탐지 정확도 95%와 3초 알림 기준은 강사 양식 예시 값을 준용했다. \[제안\]

| ID | 지표 | 제안 목표 | 측정 방법 |
| --- | --- | --- | --- |
| KPI-01 | 지진 징후 감지부터 TB1 출발 지시까지 지연 | 5초 이내 | 트리거 시각과 출발 지시 시각의 차이 |
| KPI-02 | 요구조자 탐지부터 DB 저장·TB2 통지까지 지연 | 3초 이내 | 탐지 시각과 TB2 통지 수신 시각의 차이 |
| KPI-03 | 대상이 시야에 있을 때 사람(인형) 탐지 성공률 | 95% 이상 | 시연 시퀀스 N회 중 성공 비율 |
| KPI-04 | 관리자 화면 반영 지연 | 3초 이내 | 이벤트 시각과 화면 표시 시각의 차이 |
| KPI-05 | 출구 구조 인원 카운트 일치 | 실제 통과 인원과 일치(시연 시퀀스 기준) | 실제 통과 인원과 화면 카운트 비교 |
| KPI-06 | 미구조 대상을 "구출 완료"로 잘못 표시한 건수 | 0건 | 시험 시퀀스 전체에서 오판 건수 집계 |

KPI-06은 시나리오 7번의 완료 판정이 부재 증거에 의존하는 위험을 통제하기 위해 추가했다. \[제안\]

## 4. 프로젝트 범위 (Project Scope)

범위는 팀 시나리오 1\~7번의 감지, 정찰, 구조 지원, 출구 확인, 완료 판정까지이며, 실제 구조 행위(이송·응급처치)는 제외한다. 시연은 사람 대신 인형을 사용한다. \[확정: 포함 범위·인형 / 제안: 제외 범위\]

### 포함 범위 (In Scope)

- 고정 카메라 A의 지진 징후 감지(영상 흔들림, 화면 가려짐)와 재난 모드 전환 \[확정\]
- 정찰 로봇 TB1의 출발, 실시간 지도 갱신(SLAM), 사람 탐지, 좌표 DB 저장 \[확정\]
- 구조 지원 로봇 TB2의 구급상자 탑재, 대기, 명령 수신 후 출동 \[확정\]
- 기준 지도 대비 장애물 갱신 모니터링과 사람 좌표 표시 \[확정\]
- 출구 카메라 B의 구조 인원 탐지·카운트와 DB·관리자 화면 반영 \[확정\]
- TB1의 재확인(LiDAR·카메라)과 지도상 "구출 완료" 표시 \[확정\]
- 관리자 화면과 DB(좌표, 이벤트, 카운트) \[확정\]

### 제외 범위 (Out of Scope)

- 요구조자 이송, 응급처치, 건강·부상 판정. 구급상자는 운반만 하고 사용은 현장 인력이 한다 \[제안\]
- 계단·장애물 더미 등 험지 주행 \[제안\]
- 실제 건물·옥외 적용, 실제 사람 대상 시험 \[제안\]
- 실제 지진 센서(진동계) 연동. 지진 감지는 카메라 기반 시연으로 한다 \[제안\]
- 장기 데이터 저장 및 백업 솔루션 (양식 예시와 동일) \[제안\]

### 옵션 범위 (시간이 남을 때)

- 온도 변화 모니터링: TB2가 서버실에서 온도 센서 값을 영상으로 읽고 DB에 전달 \[확정\]
- 온도 히트맵과 3D 맵 작성 \[확정: 옵션\]. 기본안은 2D 지도 위 온도 오버레이이며 3D는 별도 검토한다 \[제안\]

옵션은 핵심 시나리오와 TB2의 역할이 겹치므로 본 범위 확정 뒤 별도로 합의한다. (13장 OI-07)

## 5. Use Case

시스템은 8개 Use Case로 구성되며, 지진 징후 감지(UC-01)에서 구출 완료 확인(UC-07)까지 한 방향으로 흐르고 온도 모니터링(UC-08)만 옵션이다. \[확정: 팀 시나리오 1\~7번과 옵션 / 제안: UC 구분과 ID\]

### 5.1 액터

| 액터 | 구분 | 역할 |
| --- | --- | --- |
| 관리자 | 사람 | 관리자 화면에서 지도, 사람 좌표, 구조 인원, 구출 상태를 확인 |

| NFR-07 | 성능 | 관리자 화면의 정지 명령은 1초 이내에 로봇에 전달되어야 한다(양식 예시의 1초 기준 준용) | \[제안\] |
| NFR-08 | 규정 준수 | 상용화 시 로봇 안전 규격과 영상 개인정보 규정을 검토한다. 시연 범위는 인증 대상이 아니다 | \[제안\] |

NFR-08의 규정 후보는 다음과 같으며 이 시스템에 적용되는지는 확인하지 못했다. 무인 산업용 트럭 안전 규격 ISO 3691-4는 AGV와 AMR을 포함하지만, 공공 구역에서 쓰는 트럭은 ISO 13482 대상이라고 규격 소개 페이지에 적혀 있다. 건물 내 구조 로봇이 어느 쪽에 속하는지는 별도 확인이 필요하다. 해당 규격 2020판은 2023판으로 대체되었다고 표시되어 있다. ([ISO 3691-4:2020 소개 페이지](https://genorma.com/en/standards/iso-3691-4-2020)) 영상 촬영에는 개인정보 보호법의 영상정보처리기기 관련 조항 검토가 필요하다. \[미확인\]

## 10. 종속성 및 제약조건 (Dependencies and Constraints)

시스템은 사전 구축한 기준 지도와 로컬 네트워크에 의존하고, 평탄한 실내 바닥과 인형 시연이라는 제약 안에서만 검증할 수 있다. \[제안\]

### 종속성

- 로봇, 카메라, 서버를 잇는 로컬 네트워크(Wi-Fi) 제공 \[가정\]
- 사전 구축한 기준 지도. 시나리오 4번의 "기존 지도"에 해당 \[제안\]
- 고정 카메라 A·B의 설치와 시야 확보 \[확정\]
- 요구조자를 대체할 인형과 시연 환경 구성 \[확정\]
- TurtleBot4 2대와 충전 도크 \[가정\]
- SLAM, 인식, DB를 처리할 PC 또는 서버. 사양은 미확인 \[가정\]

### 제약조건

- 개발 기간과 예산의 한계. 발표일과 일정은 확인하지 못했다 \[미결정\]
- 휠 베이스 로봇이므로 평탄한 실내 바닥만 주행한다. 계단과 잔해 구간은 대응하지 못한다 \[제안\]
- 2D LiDAR는 스캔 평면 높이의 물체만 보므로 낮게 놓인 인형은 장애물로 잡히지 않을 수 있다 \[제안\]
- 시연 환경의 크기와 구조는 직접 구성해야 하며 아직 정해지지 않았다 \[미결정\]
- 인형은 스스로 이동하지 못하므로 "구조되어 출구로 이동"은 시연자가 수행한다 \[제안\]
- 지진은 실제로 발생시킬 수 없으므로 카메라를 흔들거나 가리는 방식의 시연용 트리거를 쓴다 \[제안\]

## 11. 위험 및 완화조치 (Risks and Mitigations)

가장 큰 위험은 구출 완료 오판(R-05)과 두 로봇의 좌표 불일치(R-02)이며, 둘 다 시나리오 자체에서 나온 위험이다. 아래 판단은 문서와 시나리오 검토에 근거한 것이며 확률·영향도를 측정한 값은 아니다. \[제안\]

| ID | 위험 | 영향 | 완화조치 |
| --- | --- | --- | --- |
| R-01 | 지진 징후 오탐·미탐(가려짐은 사람이 지나가도 발생) | 불필요한 출동 또는 출동 누락 | 지표·임계값·해제 조건 정의, 반복 시험 (TR-06, FR-05) |
| R-02 | 두 로봇의 좌표 기준 불일치 | TB2가 엉뚱한 위치로 이동 | 단일 기준 지도, 공통 기준점 오차 시험, 지도 보정 시 좌표 유효성 관리 (TR-04) |
| R-03 | 인형을 사람으로 탐지하지 못함 | 요구조자 발견 누락 | 인형으로 탐지 시험을 먼저 수행하고 필요 시 모델 보정 (TR-05) |
| R-04 | LiDAR가 낮은 인형을 장애물로 보지 못함 | 완료 판정 조건이 의미를 잃음 | 인형 높이와 스캔 높이 실측, 높이 조정 또는 완료 조건 재설계 (TR-12) |
| R-05 | 구출 완료 오판("탐지 없음"에만 의존) | 미구조 대상을 완료로 표시 | 대상 지점 관측 여부와 출구 카운트 조건 추가 (FR-22, KPI-06) |
| R-06 | 여러 대상의 개별 식별 불가 | 카운트와 완료 판정이 연결되지 않음 | 고유 ID 부여 또는 대상 1개로 제한 (FR-11, OI-03) |
| R-07 | 통신·DB 장애 | 통지 지연·유실 | 로컬 보류 후 재전송, 저장 확인 후 통지 (NFR-01, TR-07) |
| R-08 | TB2의 이동 경로 막힘 | 접근 실패 | 접근 불가 사유 보고와 발견 기록 유지 (FR-16) |
| R-09 | 일정·예산 부족으로 옵션이 핵심을 압박 | 핵심 시나리오 미완성 | 핵심 시나리오 완료 후 옵션 착수 (OI-07) |

## 12. 수락 기준 (Acceptance Criteria)

수락 기준은 Use Case마다 하나 이상의 시험으로 확인하고, 마지막에 두 로봇으로 UC-01\~07 전체를 끝까지 수행해야 합격이다. 반복 횟수 N과 허용 오차는 시험 전에 확정하고, 측정 후 기준을 낮춰 통과시키지 않는다. \[제안\]

| ID | 수락 기준 | 관련 | 측정 조건 |
| --- | --- | --- | --- |
| AC-01 | 시연용 흔들림·가려짐을 가하면 정의한 조건으로 재난 모드가 전환되고 5초 이내 TB1 출발이 지시된다. 사람이 지나가는 등 비지진 상황의 오탐 허용치는 사전에 정한다 | UC-01, KPI-01 | N회 반복, 비지진 상황 N회 포함 |
| AC-02 | 기준 지도에 없던 장애물을 추가하면 TB1이 지도에 반영하고 관리자 화면에 변화로 표시한다 | UC-02, UC-04 | 장애물 위치·개수를 바꿔 N회 |
| AC-03 | 인형이 시야에 있을 때 탐지 성공률 95% 이상, 탐지부터 TB2 통지까지 3초 이내, 같은 인형의 중복 저장 0건 | UC-03, KPI-02, KPI-03 | 인형 위치·조명·각도를 바꿔 N회 |
| AC-04 | 저장된 좌표와 인형 실제 위치의 오차가 사전 확정한 허용 범위 이내이고, TB2가 해당 좌표 인근에 도달한다. 허용 범위는 미정 | UC-03, UC-05, FR-08 | 줄자 실측 비교 |
| AC-05 | TB2는 명령 후 출발하고, 경로가 막히면 접근 불가 사유를 보고한다 | UC-05, E-03 | 경로 차단 시험 N회 |
| AC-06 | 출구 카운트가 실제 통과 인원과 일치하고 3초 이내 화면에 반영된다 | UC-06, KPI-04, KPI-05 | 인형 1개와 여러 개를 모두 시험 |
| AC-07 | 구출 후 TB1 재확인으로 "구출 완료"가 표시되고, 미구조 대상을 완료로 표시한 건수는 0건이다. 대상 지점을 관측하지 못하면 "재확인 필요"를 유지한다 | UC-07, KPI-06, FR-22, FR-24 | 구조된 경우와 남아 있는 경우를 모두 시험 |
| AC-08 | DB·통신 중단 후 복구하면 이벤트 유실이 0건이고, 저장 확인 전에는 완료로 표시하지 않는다 | E-04, NFR-01 | 중단 시간을 바꿔 N회 |
| AC-09 | 두 로봇으로 UC-01\~07 전체를 끝까지 수행한다. 한 대만의 시험은 종합 합격 근거가 아니다 | 전체 | 시연 시퀀스 전체 N회 |
