# PR 4 교차 검토 반영 검증 — 2026-10-08

검토 기준은 PR 4 head `5be3d9ead835e1a698b24e75161159d6c838c67f`다. CLA-14~16과 Cursor의 CLI 출력 보완 지적을 반영한 별도 작업 사본에서 검사했다. 이 문서는 아직 push된 수정 head의 검증 기록이 아니다. 최종 작성·검토 담당은 통합 뒤 실제 head SHA에서 다시 확인한다.

## 반영 범위

- CLA-14: 수량·host tier·미사용 호스트 정책을 `ROBOT_COUNT`, `HOST_TIERS`, `REQUIRE_ALL_HOSTS_USED`에 모았다. 로봇 2대 요구는 유지하고, 호스트 정책은 CLA-01 결정 전 현재 검토 기준안임을 코드와 개발 문서에 명시했다.
- Cursor 보완: CLI는 검증된 프로파일의 실제 `tier`를 집계한다. 다른 host tier 기준안을 적용한 시험에서도 출력과 수량이 함께 바뀌는지 확인했다.
- 배치 의미: 두 로봇의 명령 소유자는 같은 PC에 있을 수 있고, 협업 조정·관제 역할도 한 PC에 있을 수 있다. 현재 모든 호스트 사용 조건은 계속 검사한다. 두 경우의 허용 조건을 시험과 문서로 남겼다.
- CLA-15: push CI는 `main`만 대상으로 하고 `pull_request` 검사는 유지한다. 변경된 GitHub Actions의 실제 원격 실행은 이번 로컬 검증에 포함하지 않는다.
- CLA-16: 물리 로봇 식별·도메인·discovery·기대 발행자·실행 전 점검의 v2 입력 후보를 `[미구현]`으로 개발 문서에 명시했다. 해당 필드를 v1에 넣는 기능이나 ROS 점검은 구현하지 않았다. 실패 시험 커밋 운영 규칙은 별도 담당이 `review-workflow.md`에 통합한다.
- 프로파일 symlink는 실제 대상 파일의 디렉터리에서 파라미터를 해석한다는 기존 동작을 문서화하고 시험했다.

이번 변경은 설정 기준안의 표현·기존 허용 동작·출력·운영 문서 정리다. 새 결함의 실패 시험을 인위적으로 만들지 않았다. 기존 ValueError 결함의 수정 전/후 로그와 2026-10-07 해시는 과거 이력으로 보존했다.
