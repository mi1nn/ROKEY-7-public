# 탐색 알고리즘 선정안 — 2026-10-13

> **기록 (2026-10-13).** 탐색 알고리즘 선정안 기록이다. 지금 현장 탐색은 explore_lite 가 아니다. 조정기가 `search_mode` FRONTIER 로 TB-6 의 다음 목표를 직접 고른다(`rescue_coordination/ros_node.py`, `rescue_contracts.grid_search`, 현장 파일 [search_area.field.json](../../config/field/search_area.field.json)). 현장 실행은 [rescue_bringup README](../../src/rescue_bringup/README.md)를 본다.

**권고: explore_lite를 기본 탐색기로 우선 채택한다.** 사용자의 최종 확인 전에는 [제안]이며, 실기 인수 완료나 정확도 최고라는 결정이 아니다. 주행 수치는 [실기 기록](exploration-field-results-2026-10-13.md)을 단일 출처로 사용한다.

## 판단 근거

| 후보 | 이번 관측 | 선정 판단 |
| --- | --- | --- |
| explore_lite | 자체 경계 소진·완료 신호, 실제 정지 관측. 기존 설치·중단·기록 절차를 재사용 가능 | 기본 후보로 권고 |
| frontier_exploration_ros2 | 자체 완료 신호와 정지는 관측했으나, 이전 미차단 환경 회차에서 비용 임계값에 따른 목표 차단·대기를 재현. 최종 차단 환경 회차는 자체 완료 신호 관측 | 대안 후보로 유지; 차단 목표와 완료 판정 확인 필요 |
| frontier_toolbox | 실제 주행 가능. 동일 목표 취소·재전송과 지도 정체로 중단; 전체 완료 신호 없음 | 기본 채택 보류; 재전송 설정과 실패 후보 처리 검증 필요 |

[측정/제안, 2026-10-13] explore_lite를 권고하는 이유는 단일 회차의 짧은 시간보다 현재 실행·종료·중단 절차를 재사용할 수 있고 추가 연결 노드가 적다는 점이다. 세 회차의 Nav2 설정은 같지만 정확한 시작 자세·배치 일치와 다회차 편차는 검증하지 않았다. 지도 확인 영역 차이를 정확도 차이로 해석하지 않는다.

## 적용 범위

1. 단독 지도 작성 시험에서는 검증한 감독·중단 절차 안에서 explore_lite를 기본 후보로 쓴다.
2. 협업 프로젝트 통합은 [D-05](../design/algorithm-decisions.md)의 후보 생성 재사용 방향과 단일 명령 발행 경계를 유지한다. upstream이 Nav2 goal을 직접 보내는 시험 구성을 그대로 협업 운영에 넣지 않는다. 이동·취소·도킹 명령은 rescue_robot이 소유한다.
3. frontier가 없다는 신호는 지도 전체 완성이나 모든 대상 발견의 증거가 아니다. 접근 가능한 구역 기준과 별도의 임무 완료 판정이 필요하다.

## 확정·운영 전 남은 확인

- 사용자가 기본 후보 채택안을 확인하고 D-05 담당이 선정 상태·통합 범위를 갱신한다. 이 초안은 기존 D-05를 바꾸지 않는다.
- 통일된 탐색 구역·시작 자세·종료 조건으로 반복 시험해 시간·경로·누락 구역을 확인한다.
- 독립 기준 지도 또는 실측으로 지도 정확도를 평가한다.
- 미탐색 경계 주변의 도달 가능한 자유 공간을 목표로 선택하고, 좌표계·footprint·경로 존재를 검증한다.
- 협업 명령 권한·중단·실제 정지·센서 단절 처리를 프로젝트 경계에서 검증한다. 이번 단독 시험을 두 로봇 협업 인수 통과로 사용하지 않는다.
