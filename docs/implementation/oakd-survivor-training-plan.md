## 1. 영상 수집

이전 #36 후속 계획의 AVI 녹화 방향을 유지한다. `image_raw`는 ROS 입력 전송 형식을 나타내며 AVI 파일의 무손실 저장을 보장하지 않는다. 실제 녹화 코덱·설정·손실 여부와 수신/저장 해상도를 기록하고 원본 비율을 유지한다.

촬영 세션마다 session ID, 실제 로봇 식별자, 전체 토픽 이름, 메시지 타입·encoding, `frame_id`, 원 ROS stamp, 수신 시각, 영상 프레임 번호·시간, 실제 수신 FPS, 녹화 FPS·코덱, 해상도, 거리·조명·가림·자세 조건을 남긴다. 영상 프레임과 원 메시지의 연결표를 별도로 보존한다. 고정 FPS로 같은 메시지를 반복 저장했다면 반복 여부도 남긴다.

짧은 시험 영상을 먼저 재생해 색상·방향·영상 길이·프레임 수·연결표를 확인한다. 이후 여러 거리·방향·자세·부분 가림·조명·복수 인형과 대상 없는 배경을 서로 다른 촬영 세션으로 수집한다. 실제 로봇 이동이 필요하면 로봇 담당과 현장 운영 규칙에 따라 별도로 진행한다.

## 2. 1초 간격 프레임 추출과 전처리

[사용자 결정] 추출 간격은 **1초**다. 영상의 실제 시간축에서 0초, 1초, 2초…에 대응하는 사용 가능한 프레임을 선택한다. 고정 프레임 수를 실제 FPS 확인 없이 1초라고 부르지 않는다. 같은 원 메시지는 중복 추출하지 않고 스트림 공백은 누락으로 기록한다. 목표 추출 시각과 실제 선택 시각의 차이도 보존한다.

영상 시간은 ROS 센서 stamp와 구별한다. 연결표가 없으면 센서 시각은 미확인으로 남기고 프레임 번호/FPS로 원 stamp를 만들어내지 않는다. 파일명과 추출 목록에는 session ID·원 영상·프레임 번호·영상 시간·원 stamp(가용한 경우)를 연결한다.

1. 디코딩 실패·깨진 이미지·과도한 중복을 점검하고 제외 사유를 기록한다. 가림·흔들림처럼 실제 환경에서 생길 어려운 사례를 전부 제거하지 않는다.
2. 색상 채널·방향·해상도를 점검한다. resize·crop·보정이 필요하면 원본과 변환 설정을 보존하고 bbox도 같은 좌표 변환을 적용한다.
3. 각 이미지에서 시연 인형의 bbox를 `survivor`로 라벨링한다. 대상이 없는 이미지는 확인한 negative로 포함하며 미라벨 대상과 구별한다.
4. 잘린 대상·가림 대상의 annotation 기준을 먼저 정하고 전체 라벨의 범위·누락·class ID·파일 대응을 확인한다.
5. 같은 촬영 세션·원 영상과 그 파생 이미지가 train/val/test에 걸치지 않도록 분할한다. 분할 비율·seed·세션 목록·dataset version·SHA256을 고정한다. 파생 증강은 분할 후 train에만 적용한다.

데이터셋 class 순서는 `names: {0: survivor}`로 고정한다. 기존 단일 클래스 person 데이터가 같은 대상 정의를 만족하는 경우에만 검토 후 재라벨링한다. label ID가 이미 0이면 이름 변경만 필요할 수 있지만 다중 클래스 데이터는 별도 remap이 필요하다. 일반 person 데이터 전체를 survivor로 자동 변환하지 않는다.

## 3. 학습과 파라미터 비교

모델·실험 값은 결과 없이 최종 채택하지 않는다. #36의 YOLO26n/s 우선 비교 계획을 후보로 이어가되 설치 환경의 지원 여부·가중치 출처·라이선스·장비 메모리를 먼저 확인한다. 비교 가능한 기준 모델 하나를 실행한 뒤 실험을 확장한다.

| 항목 | 실험 전에 기록할 내용 | 비교 방법 |
| --- | --- | --- |
| 데이터 | dataset version, split manifest, class 순서, 전처리 | 모든 비교에서 같은 분할과 대상 정의 유지 |
| 모델 | 계열·크기, 초기 가중치 SHA256, 사전학습 여부 | 파라미터 비교와 모델 n/s 비교를 별도 묶음으로 기록 |
| 학습 | epochs, patience, batch, imgsz, optimizer, learning rate·schedule, weight decay, augmentation, seed | 기준 실험에서 한 번에 한 요인 변경; 복수 변경 시 별도 조합 실험으로 명시 |
| 환경 | Python·학습 라이브러리 버전, GPU·CUDA·메모리, 실행 명령 | 동일 장비·조건 유지; 차이가 있으면 함께 보고 |
| 평가 | confidence·IoU 설정, 평가 split, 반복 seed | val로 설정을 고른 뒤 고정 test로 최종 평가 |

숫자 후보는 실제 장비와 데이터 규모를 확인해 실행 전에 실험 설정 파일로 고정한다. epochs/batch/imgsz 등 학습 설정과 confidence 등 추론·평가 설정을 구별한다. 메모리 부족·중단·재개·early stopping도 기록하고 결과가 없는 실험을 성공으로 처리하지 않는다.

비교 지표는 precision, recall, mAP50, mAP50-95, TP/FP/FN, best epoch, 실제 수행 epoch, 학습 시간, 모델 크기, 메모리 사용량이다. 동일 입력 크기·장비·평가 조건에서 지연도 측정한다. 모델 추론 시간과 카메라 수신→디코딩→추론→출력 전체 지연은 따로 기록한다. test를 반복 튜닝에 쓰지 않으며, 현장 적용 임계값과 합격 기준은 실측 후 별도 결정으로 남긴다.

## 4. survivor를 기존 관측 파이프라인에 연결

기존 모듈/API 이름 `person_pipeline.PersonPipeline`·`ConfirmationPolicy.person_labels`는 호환성을 위해 유지한다. 후속 실제 Detector 연동에서는 dataset class 순서, 학습된 모델의 class metadata, `ModelManifest.class_labels=("survivor",)`, `ConfirmationPolicy.person_labels=("survivor",)`, 출력 `DetectorOutput.class_label="survivor"`를 일치시킨다. 모델 class ID 0이 survivor인지 확인하고 가중치 SHA256을 검증한다.

person 출력 문자열만 survivor로 바꾸는 것으로 새 모델 학습이 완료되었다고 하지 않는다. 기존 모델의 person class를 사용하는 비교 기준선이 필요하면 모델·라벨 매핑과 평가 대상 정의를 별도 명시한다. 과거 person 관측·합성 시험·원본 BRD는 역사 기록으로 유지하고 새 결과와 구별한다.

survivor 클래스는 인형의 개별 신원이나 SORT track ID가 아니다. 표식·동일 대상 병합·출구 사건 연결은 [범위 Q-13](../requirements/scope.md)의 별도 결정이다. 이번 RGB 영상 학습은 #40의 RGB-D/CameraInfo/stamp 검증을 대체하지 않으며, 학습 성공만으로 지도 좌표·자동 이동을 허용하지 않는다.

## 남은 실행 순서

1. 실제 `oakd/image_raw` 입력과 기록 환경을 확인하고 짧은 AVI를 검증한다.
2. 촬영 세션을 수집하고 1초 간격 추출·전처리·survivor bbox 라벨링을 수행한다.
3. 세션별 split과 기준 학습 설정을 고정한 뒤 학습한다.
4. 파라미터별 val 비교 및 최종 test 평가를 수행한다.
5. 결과 docs·manifest를 PR로 올리고 실제 Detector 연결·RGB-D 현장 검증을 이어간다.
