# 재난 수색 파이널의 범위와 인수 조건

AMR 2대가 변화하는 재난 모사 환경에서 협업 수색하고, 발견한 대상에 접근한 결과와 위치·현장 정보를 관제에 보고한다. 이 문서는 구현할 범위를 정한다. 디렉터리·배포 구조·알고리즘 선택은 계획 PR 2, 메시지·상태 전이·시험 수치의 상세 계약은 계획 PR 3에서 검토한다.

## 완료 범위와 제외 범위

`발견`, `위치 확인`, `접근 완료`, `보고 완료`를 구분하는 것을 제안한다. 로봇이 사람을 실제 이송한 것처럼 `구조 완료`라고 표시하지 않는다. 보고의 “상태”는 관측 시각, 확인 여부, 접근 결과처럼 시스템이 관측한 내용으로 정의한다. 건강·부상·생존 상태를 확정하는 기능은 넣지 않는다.

| 포함할 기능 | 이번 범위에서 제외할 기능 |
| --- | --- |
| 두 로봇의 역할 분담과 발견 정보 공유 | 사람을 들어 올리거나 이송하는 물리적 구조 |
| 수색 중 지도 갱신과 로봇 위치 추정 | 안전지대까지 사람을 이동 안내하는 기능 |
| 통로 변화에 따른 경로 재검토 | 구호물품 **전달 장치**(매니퓰레이션)와 사람 안내. 구급상자를 **싣고 이동**하는 것은 RQ-08 로 포함(탑재 방식은 Q-16) |
| 사람 또는 합의한 시연 대상의 탐지·위치 추정 | RC카 추종을 파이널의 목표로 유지하는 것 |
| 접근 가능한 지점에서 정지하고 결과 보고 | 원본 과제·미니 산출물 전체의 보존·실행 호환 |
| 접근 불가, 위치 불확실, 통신 이상에 대한 명시적 처리 | 센서로 확인하지 않은 지진·붕괴·부상 상태의 자동 확정 |

위 제외 항목 중 사람 이송·안내·물품 전달은 RQ-04의 범위를 정리한 것이다. 상태 이름과 보고 세부 필드는 설계 제안이며 계획 PR 3에서 확정한다.

RQ-10은 AMR2가 구조대원을 뒤따르는 요구이며, 사람이 로봇에 의해 안전지대로 안내·이송되는 기능을 포함하지 않는다. 현재 수정된 시나리오는 [BRD v0.2](brd-v0.2.md)와 [SRD v0.2](srd-v0.2.md)를 따른다. RQ-11에 따라 AMR1 최초 정찰은 관제 버튼 명령을 기다린다. 아래 v0.1 표와 Q-12·Q-25의 자동 출동·구간 승인 결정은 당시 기록이며, 새 버튼 출동·연속 추종 실행 계약의 근거로 재사용하지 않는다.

QR 출구가 하나도 없으면 TB-5 시작점(대기 자리)이 출구다. ③ TB-5 는 인형을 찾자마자 출발해 인형 앞에서 기다리고, 탐색이 끝나면 인형에서 가장 가까운 출구(지도 위 실제 경로 길이)로 사람과 함께 나간다. ④ 지도 고정은 두 번: 인형 발견 때(TB-5 출동용), 탐색 완료 때(완성 지도, TB-5 는 멈춘 채 다시 정합). ⑤ 교차 관제 1단계: TB-5 우선, 번갈아 움직이기, TB-6 비켜서기(TB-5 출발 전), 두 로봇 최소 거리 미만이면 새 명령 막고 사유. 후진은 쓰지 않는다(원형 로봇이라 제자리 회전 + 전진으로 비켜섬). ⑥ 완료 판정은 탐색 완료이고, TB-6 는 재확인하지 않는다(2026-10-13 4A 의 TB-6 재확인을 뺀다). 구출 임무의 끝은 [작전 기본, 재범 확인 대기] TB-5 의 출구 도착이고, TB-6 는 탐색 완료 뒤 도킹 접근 지점으로 간다 [작전 기본, 재범 확인 대기]. ⑦ 탐색이 끝났는데 인형이 없으면 TB-5 는 출발하지 않고 「생존자 없음」으로 끝낸다. 이 변경으로 같은 날 앞선 「인형 + 출구를 찾으면 지도 고정」·순찰 지점 안·TB-6 재확인은 대체된다. 원문: "TB-6의 경우에는 해당 출구를 기록하고 계속 탐색을 지속하고, 모든 맵이 탐색이 완료되었다면, 해당 정보를 TB-5에 보내서 사람(있다면) 위치 + 최단 출구의 위치를 송신", "인형 찾자마자로 한다음에 그럼 TB가 교차될때 좁은 길 같은거 잘 통과할 수 있도록 관제하는 로직을 추가할까?", "탐색 완료. TB-6는 재확인하지 않는다." | 작전·총괄, 협업·관제, 인식, 로봇·지도; 저장소 소유자 채택 |

질문 항목은 설계·시험 담당이 해결할 작업이다. 모든 항목에 즉시 사용자 답변이 있어야 이 문서 PR을 검토할 수 있다는 뜻은 아니다. 다만 해당 항목에 의존하는 구현·실기는 확인 전 완료로 판정하지 않는다.

PR 초안 작성과 검토는 병렬로 진행하며 앞 PR의 머지를 기다리지 않는다. 의존하는 PR은 상위 브랜치 위에 쌓아 diff와 기준 SHA를 구분한다. Codex는 피드백을 일괄 반영한 뒤 PR별 최종 검토를 수행하고 Cursor에 인계한다. Claude는 로직·계획 검토, Cursor는 검증·수정·머지를 맡는다. main 머지는 의존 순서를 지킨다. 수정 후 재검토·하위 PR 정리·인계 조건은 [역할별 검토 지침](../process/review-workflow.md)에 둔다. 교차 검증과 실제 두 로봇·네 PC의 인수 시험은 별개다.
