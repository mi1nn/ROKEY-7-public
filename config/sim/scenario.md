# 시뮬레이션 회차가 돌아야 하는 모습

재범이 정했다(2026-10-16). 시뮬레이션 회차의 기록은 아래 네 단계마다 통과/실패와 시각을 적는다. 시뮬레이션은 현장 코드를 그대로 쓰고, 현장 값과 다른 것은 [시뮬레이션에서 찾은 것을 현장 코드로 옮기기](../../docs/process/sim-to-field.md) 규칙대로 드러낸다.

## 시험장

- **주 시험장은 sim1(평면도 실습장 `worlds/arena.sdf`)이다.** 실제 환경과 가장 비슷해서 매 회차를 여기서 돌린다. 목표는 아래 네 단계를 모두 통과하는 것이다.
- **sim2(`worlds/sim2.sdf`, TurtleBot4 시뮬레이터 미로)는 보조다.** sim1이 막혔을 때 탐색 로직만 따로 볼 때 쓴다.
- 결정: 재범, 2026-10-16 02:0x(「실제 환경과 가장 비슷한 sim1에서 계속 테스트하는게 낫지 않을까?」).

## 단계

| 단계 | 돌아야 하는 모습 | 기록할 것 |
| --- | --- | --- |
| 1 | TB-5와 TB-6가 모두 언독하면서 시작한다 | 두 로봇의 언독 시각 |
| 2 | 재난을 선포하면 TB-6가 SLAM을 돌리며 곧바로 움직이고, 한자리에 서 있지 않고 맵 전체를 훑는다 | 선포부터 첫 이동까지의 시간, 멈춘 구간(시각·길이·이유 로그), 훑은 넓이(최종 지도의 빈 칸 수 / 실습장 바닥 칸 수) |
| 3 | 웹 지도에 터널과 인형 위치가 뜬다 | 터널 1·2(`overhead_passages`)와 인형 위치가 웹 지도에 처음 뜬 시각, 확인용 정답 위치와의 거리 |
| 4 | 인형을 찾는 순간 TB-5가 출발한다 | 인형 발견 로그부터 TB-5 작업 SEND와 이동 시작까지의 시간 |

- 한 단계라도 막히면 멈춘 이유를 「실물에서도 날 것 / 시뮬레이션 탓 / 모름」으로 나누고 근거를 적는다. 실물에서도 날 것은 현장 코드에서, 시뮬레이션 탓은 `config/sim/`·`scripts/sim/`에서 고친다.
- 확인용 정답 위치(Gazebo)는 기록에만 쓰고 어떤 노드에도 주지 않는다. 로봇은 지도를 모르고 시작한다.
- 한 PC에서는 한 번에 한 시뮬레이션만 돌린다. 두 Gazebo가 같이 돌면 실시간 비율이 떨어져 깊이 입력이 늦고, 그 정지는 시뮬레이션 탓이 된다(2026-10-16 3회차 00:12~00:26).
