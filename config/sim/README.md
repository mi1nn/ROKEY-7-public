# 시뮬레이션 입력 (Gazebo 세계)

시뮬레이션 트랙 1단계(재범 결정 2026-10-15 저녁)에서 쓰는 Gazebo(gz Harmonic) 세계와 그 입력이다. 목표는 실제 실습장을 딴 세계에서 가상 TB-6 이 SLAM 으로 지도를 만드는 것이다.

**실제 지도는 세계를 만드는 입력으로만 쓴다.** 시뮬레이션 중에는 이 지도를 어떤 ROS 토픽이나 map_server 로도 내지 않는다. 로봇이 쓰는 지도는 가상 TB-6 SLAM 이 새로 만든 것뿐이다. 실제 시나리오와 같다(기준 지도 없음 → TB-6 SLAM → 고정 → 두 로봇 AMCL).

## `maps/` — 입력 지도 원본

mu-03 의 현장 지도를 실기가 파일 그대로 보냈다(gzip + base64, 2026-10-15). 받은 뒤 sha256 이 모두 같았다.

| 파일 | 무엇 | 크기 | sha256 |
| --- | --- | --- | --- |
| `live_map.yaml` | 2026-10-14 19:35 TB-6 SLAM 중 스냅숏(mu-03 `robotnet/live6`) | | `c05b49f64ee815e1d9cef7c716d4443fdb9dbd12a599f671008af456e7a957ea` |
| `map_3d44bf26cf8e.pgm` | 위 지도 그림 | 154 × 85 칸, 0.05 m, 7.7 × 4.25 m | `3d44bf26cf8eb3cb92a95c56d8fbe323c0944af1d5327f875658e989c85b24e0` |
| `tb6_map_191936.yaml` | 2026-10-14 19:19 TB-6 SLAM 저장(끝 줄바꿈 없음, 원본 그대로) | | `a17c348d022554096fbac3a87125c53b281150ea3fae09485239ab5c0fed27f1` |
| `tb6_map_191936.pgm` | 위 지도 그림 | 99 × 84 칸, 0.05 m, 4.95 × 4.2 m | `ab16f85fbfdff8e5682e9e51ee365d06c5bcf8173f2dc0a85a9b9b3569764e5d` |

- 칸 값은 0(점유)·205(모름)·254(빈칸) 세 가지다.
- 두 지도 모두 실습장 전체를 다 돈 지도인지는 모른다(가장자리에 모름 칸이 많다, 실기).
- 10-10 `pre_quake` 지도는 옛 배치라 쓰지 않는다.

## `worlds/` — 세계

| 파일 | 무엇 |
| --- | --- |
| `practice.layout.json` | 배치 목록. 벽 높이·두께·색, 바닥 색, 잡음 거르기, 로봇 출발 자리, 지도에 없는 물체. 재지 않은 값은 `"estimate": true` 다 |
| `practice.sources.json` | 이 세계를 만든 지도 파일 이름 |
| `practice.sdf` | 만든 세계. 손으로 고치지 않는다 |
| `practice.spawn.json` | 로봇 출발 자리. 실행 스크립트가 읽는다. 도크는 TurtleBot4 spawn launch 가 로봇 옆에 둔다 |

다시 만드는 명령은 아래와 같다. 시험(`tests/test_sim_map_to_world.py`)은 저장소의 `.sdf`·`.spawn.json` 이 지금 지도와 배치 목록으로 만든 결과와 같은지 본다.

```bash
python3 scripts/sim/map_to_world.py --map config/sim/maps/live_map.yaml \
  --layout config/sim/worlds/practice.layout.json --name practice --out-dir config/sim/worlds
```

- 벽은 지도의 점유 칸 가운데 3칸 미만 덩어리(SLAM 잡음)를 뺀 나머지를 사각형으로 묶어 세운다. 684칸이 상자 149개가 됐다. 높이는 MDF 판 0.41 m 다[측정, 재범 2026-10-15]. 두께 0.01 m 는 사진으로 본 값이다[추정]. 두께는 지도가 못 본 벽을 선분(`"kind": "wall"`)으로 더할 때 쓴다. 지도에서 세운 벽은 칸 크기(0.05 m) 그대로다.
- 세계 좌표는 지도 좌표 그대로다. 지도 원점은 10-14 TB-6 출발 자세라 실습장이 약 9° 기울어 보인다. 가상 TB-6 를 (0, 0, 0) 에 세우면 시뮬레이션 SLAM 지도도 같은 좌표에서 시작한다. 그래서 실제 지도와 겹쳐 볼 때 변환이 필요 없다.

## 실측과 대조 (2026-10-15)

지도를 9° 돌려 보면 긴 벽 세 줄이 x ≈ −8.8, −5.2, −3.2 m 에 선다. 간격은 3.6 m 와 2.0 m 이고 합은 5.6 m 다. 재범 실측 「세로 3.56 m + 2.01 m」(합 5.57 m)와 맞는다. 가운데 줄(−5.2 m)이 두 구간의 경계로 보인다[해석, 확인 중]. 가로 3.43 m 는 위쪽 벽(y ≈ 3.7 m)만 지도에 뚜렷하고, 아래쪽 벽은 거의 잡히지 않았다.

## 아직 없는 것

- 흰 상자, 인형(노랑·빨강), 출구 QR 판(텍스처), 머리 위 통로(바닥에서 0.46 m), 기둥과 사각 칸의 실측 위치. 위치를 모르므로 `objects` 는 비어 있다. 값이 오면 배치 목록에 넣고 다시 만든다.
- 지도가 못 본 바깥 벽(아래쪽). 실측 바깥 크기로 선분을 더할 수 있다.
- **로봇 출발 자리는 [미확인] 이다(원점 임시).** 지금 값 TB-6 (0, 0, 0) 은 지도 원점이다. 지도 원점은 slam_toolbox 가 시작할 때의 odom 원점이고, Create3 odom 은 켜지거나 리셋된 자리가 원점이라 출발 자리와 같다는 보장이 없다[추정, 작전]. 실제로 (0, 0) 은 지도 범위(x −9.3 ~ −1.6 m)보다 1.6 m, 벽 직사각형보다 약 3 m 동쪽 바깥이다. 사진에서는 두 로봇이 벽 안 오른쪽, 각자 도크 옆에 서 있다. TB-5 는 TB-6 오른쪽 1.86 m 다(줄자, 2026-10-15). 벽 모서리 기준 실측이 오면 `practice.layout.json` 의 `robots` 만 바꾸고 다시 만든다.
